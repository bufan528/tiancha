# 一级市场行业投资价值评分模型（设计说明 v1.0）

> 本文件是产品核心评分逻辑的设计基准。`config/scoring.json` 中的维度、权重、阈值必须与本文完全一致；本文同时作为最终交付文档保留。

## 1. 设计目标

面向一级市场早期投资，对一份新识别出的行业赛道，结合研报证据与 Wind 行业指标，输出 **0–100 分总分 + 评级**，判断是否纳入投资储备库。评分追求「可解释、可配置、可追溯」：每个维度有锚点描述，每次打分保留理由与历史。

## 2. 评分维度与权重（7 维，合计 100%）

| 维度 key | 名称 | 权重 | 考察内容 |
|---|---|---|---|
| market_growth | 市场空间与增速 | 20% | TAM 规模、近 3 年 CAGR、未来 3–5 年预期增速 |
| policy_env | 政策与监管环境 | 15% | 产业政策支持力度、监管确定性、是否卡脖子/鼓励类 |
| competition | 竞争格局与壁垒 | 15% | 集中度、技术/牌照/资源壁垒、头部玩家格局 |
| tech_maturity | 技术成熟度与趋势 | 15% | 技术路线确定性、代际迭代风险、研发活跃度 |
| commercialization | 商业化与产业链 | 15% | 落地阶段、付费意愿/客单价、产业链完整度、毛利水平 |
| exit_env | 退出与资本环境 | 10% | IPO 通道（含科创板/港股 18A/18C）、并购活跃度、一二级估值差 |
| risk_level | 风险因素（逆向） | 10% | 技术失败/需求证伪/政策反转/供应链风险；风险越高得分越低 |

**总分计算**：总分 = Σ(各维度 0–10 子分 × 权重) × 10，四舍五入到整数，区间 0–100。

## 3. 维度打分锚点（每维 0–10 分）

通用锚点：**9–10 = 显著优于行业基准**；**7–8 = 明确正面**；**5–6 = 中性/有分歧**；**3–4 = 偏负面**；**0–2 = 重大风险或证据缺失**。各维度具体锚点：

- **market_growth**：9–10 = TAM>千亿且未来 CAGR>25%；7–8 = TAM 数百亿级且 CAGR 15–25%；5–6 = 百亿级、个位数增长；3–4 = 成熟存量市场；0–2 = 萎缩/无规模
- **policy_env**：9–10 = 国家战略明确鼓励且监管清晰；7–8 = 地方/行业政策支持；5–6 = 中性；3–4 = 监管收紧预期；0–2 = 政策打压/合规红线
- **competition**：9–10 = 壁垒极高、格局未定、先发红利；7–8 = 有一定壁垒、头部初现；5–6 = 混战；3–4 = 巨头垄断难切入；0–2 = 无壁垒同质化
- **tech_maturity**：9–10 = 路线确定且仍在快速迭代；7–8 = 已商业化、有优化空间；5–6 = 技术路线有分歧；3–4 = 中试/早期；0–2 = 原理性失败风险
- **commercialization**：9–10 = 已放量、付费意愿强、毛利高；7–8 = 标杆客户落地；5–6 = PoC 阶段；3–4 = 商业模式未验证；0–2 = 无付费场景
- **exit_env**：9–10 = 明确 IPO 通道 + 一二级倒挂收窄；7–8 = 可预期退出；5–6 = 一般；3–4 = 通道狭窄；0–2 = 退出无望
- **risk_level**（逆向）：9–10 = 风险低且可控；7–8 = 主要风险可缓释；5–6 = 风险中等；3–4 = 风险偏高；0–2 = 致命/不可逆风险

## 4. 评级分档与入池阈值

| 总分 | 评级 | 含义 | 处置 |
|---|---|---|---|
| ≥ 80 | A | 核心储备 | 进入 reserve，优先安排深度研究与尽调 |
| 65–79 | B | 重点关注 | 进入 reserve，持续跟踪 |
| 50–64 | C | 观察 | 不进储备库（watch），积累证据再评 |
| < 50 | D | 暂缓 | parked，归档备查 |

- **入储备库阈值：65 分**（config/scoring.json 中 `thresholds.enter_pool` 可调）
- 每次打分写入 scores 表留痕；同一行业新研报到来后重新打分，档案与评分历史均保留，不覆盖旧值。

## 5. 可配置性

以上权重、锚点、阈值全部落在 `config/scoring.json`，Web 端「评分配置」页（`GET/PUT /api/scoring/config`）可在线调整；LLM 打分时必须把当前配置里的锚点描述作为 prompt 的一部分，保证「改配置即改打分口径」。
